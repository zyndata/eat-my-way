### 2026-08-28 — Scaffolding

1. **Deploy target is `eatmyway.gorny.dev`**, on the same VM as szok.gorny.dev.
2. **nginx terminates TLS, not Caddy.** PLAN.md originally had Caddy hold 443 with automatic
   HTTPS; nginx already owns 80/443 on that host. Caddy now listens on plain HTTP `:8080`,
   published on `127.0.0.1` only, and stays the sole source of the security headers (nginx must
   not add its own, or browsers see duplicates). PLAN.md Architecture and Phase 1 updated.
3. **The bundle is built in CI, not on the server.** The `Dockerfile` is `FROM caddy:2-alpine`
   plus a prebuilt `dist/`, instead of the multi-stage Node build PLAN.md first described.
   Reason: the VM is small, and a CI-built artifact is the same bytes everywhere. Consequence:
   `docker compose up` requires `npm run build` first — hence the `docker:up` script.
4. **Release model: `dev` → `main` → `vX.Y.Z` tag**, mirroring S.Z.O.K. A plain push to `main`
   does not deploy; only the tag does. Driven by the `/release` skill.
5. **CHANGELOG.md is generated by git-cliff** from Conventional Commits, not hand-written.
   This changes the end-of-phase ritual: the commit message is the changelog entry, and the file
   is regenerated with `npm run changelog`. `git-cliff` becomes a devDependency in Phase 1 so
   both machines produce identical output.
6. **MIT license, public repository.** No credentials in the repo; `VITE_*` values are public by
   design and the Gemini key lives only in the user's vault.
7. **Temporary CI guard.** `.github/workflows/ci.yml` skips its npm steps while `package.json`
   does not exist, so CI is green before Phase 1. Phase 1 removes the guard (task 7).
8. **Cross-platform checkout (Windows + Linux)** is a hard constraint: LF via `.gitattributes`,
   no absolute paths, no platform-only scripts in the build path. See docs/DEVELOPMENT.md.
